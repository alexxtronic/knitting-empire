# AGENTS.md

Notes for AI coding agents (Codex, Claude Code and others) working on Knitting Empire. People should start with `README.md`, which explains the game, the project layout and how to add content.

## The project

- A cozy farm, knitting and life-sim game made in **Godot 4.7** (GDScript, Forward+). Main scene: `main.tscn`. Most of the game logic is in `scripts/main.gd`, and the UI is in `scripts/hud.gd`.
- Content is data, not code. Furniture, crops, prices, villagers, dialogue and areas are in `data/*.json`, and story scenes are plain-text files in `data/scenes/*.scene`. To add content, edit the data first. `README.md` ("Adding content without code" and "Writing story scenes") explains the formats.
- **The direction is `docs/DIRECTION.md` (Alex, 2026-11-15): read it before adding a feature.** The game is the knitting empire's loop: find animals, round them up with the dog, knit their fibre, sell, reinvest. Sweaters are the economy: every coin comes from one. Jobs pay petty cash and build friendships, and buildings serve the story and the business.
- The owner is Alex D'Amore. The art style rules are in `docs/STYLE_GUIDE.md` (a draft; don't treat it as final).

## Run it

```bash
/Applications/Godot.app/Contents/MacOS/Godot --path .
```

If you add or replace files under `assets/`, import them first. This writes their `.import` files:

```bash
/Applications/Godot.app/Contents/MacOS/Godot --headless --path . --import
```

## Test it: the autotest must pass

Every change to the game's code or data must keep the autotest green. A change that only adds or rebuilds an asset (a model, its textures, its `model` line in `data/furniture.json`) doesn't need the full run (Alex, 2026-11-12: "we don't need autotests for every single asset we make"): import it, run the matching quick check if there is one (`--only=house`, `--only=bench` and so on, a few seconds each) and look at its screenshot. The autotest opens a real game window (the renderer is needed, so it can't run headless) and plays through the game: farming, building, the town, the story (Act 1) and Rowan's romance scenes, plus sound, the title screen, settings and tips. It prints a `PASS` or `FAIL` line for each check and saves screenshots to the folder you give it. A full run takes about 6 to 8 minutes.

```bash
/Applications/Godot.app/Contents/MacOS/Godot --path . --resolution 1280x800 -- --autotest=/tmp/ke_shots > /tmp/ke_autotest.log 2>&1
grep -c '^PASS' /tmp/ke_autotest.log   # expect 236 at the time of writing
grep -E '^FAIL|SCRIPT ERROR|Parse Error' /tmp/ke_autotest.log   # expect nothing
```

## The world layout: `data/world_layout.json`

Alex arranges the map himself in the game: Settings > God mode > "Edit the world" (`scripts/god_mode.gd`; the switch only shows when the game runs from the project with the Godot editor build, never in an exported game). He can move, turn, copy and delete scenery and buildings, and paint dirt, gravel and cobblestone roads. It saves to `data/world_layout.json`, which every launch applies on top of what the code builds, so that file is the final map.

- Don't hand-edit or delete `data/world_layout.json`, and commit it when it changes. It is Alex's work.
- The autotest runs with the layout applied, because that's the game players get. If a check fails only because of where something now stands (a bench the test sits on was moved, say), fix the check to find the thing rather than the layout. `-- --nolayout` runs the game as the code builds it, to tell the two apart.
- Once a kind of scenery (a tree kind, rocks, a bush kind, tufts) has been edited, its full list is in the file and replaces what `world.gd` and `nature.gd` scatter. Changing their random placement no longer moves that kind. Single things (shop fronts, fountain, stall, signposts, barn, mailbox, plots, lamp posts, benches) are stored as changes named by kind and original position (`decor_lantern@46.00,-5.40`). If you move one in code, its saved change no longer matches: the game prints a `world layout:` warning and keeps the entry in the file.
- Nora's furniture (her house and the yard pieces a new game starts with, `main.furniture`) is editable too. Once any of it is arranged in the editor, the file gets a `"house"` list: the whole set as it stood, which `_new_world()` then furnishes a new game from instead of its built-in list. A catalog piece placed inside the house joins it. A player's own game keeps its furniture in the save.
- Guardrail: the god checks fail if any Furniture node in the world can't be picked up (on its own, or as part of something that can, like a shop's furnishings), or if any model in `assets/props` is missing from the Place list. If you add a new kind of thing that trips this, register it in `GodMode.collect()`; don't weaken the check.
- She, and the dog, can walk anywhere on the map until it ends (Alex, 2026-11-14): `main.whole_map()` is the grid's bounds short of the sea, and `main.walk_areas()` also adds the ground round each building wherever the editor puts it. What's on the map stands in the way: trees, rocks and solid models anywhere in `Regions.BOUNDS` block the grid (`GodMode._block_rects`), and so do the swamp's pools. The grid covers x -96..144, z -100..62 (`GRID_ORIGIN`, `GRID_SIZE`; the lands round the farm make it that big). `--only=dog` checks he can run to the swamp's far edge and into the woods between the lands.
- Anything new you add to the world should be editable too: build it as its own node and register it in `GodMode.collect()`, or scatter it as a MultiMesh under `nature` (those are picked up automatically). Loose boxes added straight to the world root can't be selected (the sheep pen and the pond were built that way at first). Every model in `assets/props` shows up in the editor's Place list by itself.
- The sheep pen can be moved: use `main.pen_rect`, not the `PEN` constant, for where it is now.
- Painted roads replace `World.PATHS`, `Town.PATHS` and the plaza cobbles as soon as the file has a `roads` entry. Read `god.road_at(x, z)` rather than those constants if you need to know what's underfoot.

- Rosewood Cottage is hidden for now (Alex, 2026-11-13): `Town.COTTAGE_ON` is false, so there's no cottage, for-sale sign or garden hedge, no sale on Gary's menu and no rent, and the town checks skip it (they check it's gone instead). An old save that bought it keeps the flag but gets nothing from it (`main.cottage_owned()`). Set it true to bring it all back.

## The lands round the farm: `scripts/regions.gd`, `data/regions.json`

- Four lands sit round the farm and Maple Grove, all in one continuous world (no loading screens): Mirewood Swamp to the west, Greyspine Foothills to the north with the mountain range behind them, Saltmeadow Beach and the sea to the south, Eastfield Meadows to the east. The names are draft text until Alex approves them.
- Each land's walkable rect, ground colours and scatter list are in `data/regions.json`; the `trails` there are the dirt paths that lead out to them. `Regions.build()` makes the ground, trails, swamp pools and mist, sea and mountains, and scatters the scenery as MultiMeshes under `main.nature`, one kind per land and model (`swamp-rock_cluster`), so the world editor can move them and the saved layout's lists for the farm's own kinds don't replace them.
- The mountains are one heightfield mesh behind the foothills (out of reach; she can't climb them). The sea is a plane with `shaders/sea.gdshader`; its shore is `regions.shore_z`. Far scenery fades out by `Regions.VIEW` distances to keep the frame rate up.
- If the world grows much further, stream far lands in and out by distance in the background rather than adding loading screens.

## Building walls, Gary's plots and furniture colours: `scripts/house_builder.gd`, `data/economy.json` "building"

- B (the `build` key) opens Build & Buy at any time, as before. Its Walls row (Wall, Doorway) picks up the wall tool (`main.builder`, Alex 2026-11-15): she lays walls one at a time on a 2 m grid, each paid for as it goes up (`building` "wall" and "door"; a 4 x 4 m room against the house is six walls, about three days of sweater sales). A wall starts against her house or a wall she built; clicking one of her own walls takes it down for half back. Right click or Esc puts the tool down.
- What she built is `Game.flags["built_walls"]` (edge key "x,z,h" or "x,z,v" -> "wall" or "door", see the script's header); rooms aren't saved but worked out from the walls (`builder.compute()`). A room that shares a wall with the house joins it: `house_spans()` tells `_rebuild_house()` where to open a doorway in the house's own walls (`_wall_line`, `_lintel`), and `build_into()` gives each room the house's plank floor and gable roof (`_house_roof(..., "house")`; roofs of one group lift together). Her walls are in `wall_rects`, so they block the walking grid; rooms count as indoors (`builder.indoors`, `encloses`) for footsteps, furniture and digging.
- Building plots: Gary's menu has "Buy a plot" rows (`building` "plots", `builder.buy_plot`, `Game.flags["plots_owned"]`). A plot she owns is staked out and its trees and rocks are cleared (`forage.apply()` asks `builder.clears()`). Off her farm she can only build on her own plot, where the first wall also pays `new_house_fee` for a new house's foundations. The old "Expand House" button still works and refuses if her walls are in the way.
- The world editor lists her walls (`El.built`, `GodMode.sync_built()`): moved or deleted there, they go back on the grid when it closes (`builder.from_editor`). They're kept in her save, never in `data/world_layout.json`.
- Colours: a piece whose `data/furniture.json` entry has `colors` (its `parts`, the model's material names, and a `palette` from the file's `palettes`) shows colour swatches while she holds it in build mode (`hud.set_colors`, `main.recolor_held`). ## The sun and the moon: `scripts/sky_bodies.gd`

- One DirectionalLight3D (`main.sun`) is the sun by day and the moon by night. `SkyBodies.update()` (called from `Lighting.update()`, after `main._update_lighting()`) points it at the sun, then swings it over to the moon during the dim part of dusk, or to faint high starlight when the moon is down. The sky shader draws both discs from `sun_dir` and `moon_dir`, not from the light.
- The moon goes round once a season by the game's days (`SkyBodies.phase()`, `LUNAR_DAYS` = 28): new on day 1, first quarter on the 8th, full on the 15th, last quarter on the 22nd, moving on a little each game hour. It trails the sun by its phase, so a full moon rises at sunset and is up all night. Moonlight runs from `MOON_NEW` to `MOON_FULL` with how much of the disc is lit, and the night's sky light goes with it. `SkyBodies.phase_override` fixes the phase for tests and screenshots.
- Clouds come and go on their own: `SkyBodies.cloudiness(day, hour)` drifts between clear, fair, broken and nearly overcast in spells of a few game hours, the same sky for the same day and hour every time. Rain covers the rest of the sky. A cloudier sky dims the sun a little and softens its shadows. `clouds_override` fixes it for tests.
- The grass has light and dark patches (`shaders/grass_patches.gdshaderinc`, shared by `ground.gdshader` and `grass_blade.gdshader` so the blades and the ground under them agree): broad sunnier and deeper drifts and smaller clumps. `patch_strength` on either material turns them down.
- `Lighting._depth()` works against the flat look by day: a stronger, warmer sun over a cool blue fill, a clearer sky at midday, and the distance fog kept off most of the sky (Godot fogs the sky fully by default, which had hidden the sky shader's gradient, clouds and stars).

## First person: `scripts/first_person.gd`

- V (or Menu > First person) hands the camera to `main.fps`. Like cinematic mode, `_update_camera()` returns at once while `fps.active`; `_input()` asks `fps.handle_key()` first (keys it doesn't use, like the hotbar and the bag, go on as usual) and `_unhandled_input()` gives the mouse to `fps.handle_mouse()`. The clock runs and the HUD stays.
- The camera sits between her `LeftEye` and `RightEye` bones, `FirstPerson.FORWARD` in front, with most of the walk's head bob smoothed out (`BOB`). Her body turns with the view, and her head turns the way it looks (`_gaze_for`).
- WASD sets `player.steer`; `player.gd` walks her that way with her usual speeds and easing, sliding along anything `player.steer_ok` (the walking grid) says is solid. S plays the steps backward. A click's walk (an action on something far off) still uses her path.
- Her head is hidden from this camera only: her body meshes switch to shadows only (so her shadow keeps its head), and a copy of each without the triangles that follow the `Head` bone and the bones under it is drawn instead, sharing her skeleton and skin; their blend shapes (her grip, her knitting hands) are copied across each frame. The model isn't changed. If a character's hair or hat isn't weighted to the head, it would show.
- While it's on, the walls are up and every roof stays on round her.
- Roofs: every building has one, and they all follow one rule. From above (third person) a roof lifts off while she's inside, so you can see her; in first person it stays on. The barn (`World.update_barn`) and the walk-in shops (`Interiors.update`) lift theirs; Nora's house and Rosewood Cottage get a gable roof from `_house_roof()` in `main.gd` (shingled slopes, eaves, a plastered gable whose underside is the ceiling), and `_roof_lifted()` also lifts them in building mode, while placing a piece and in the world editor, so the rooms can be furnished. While a house's roof is on, all its walls stand: only a house with its roof lifted cuts the walls toward the camera down (`_update_walls`). The house's roof is rebuilt with it when it grows. A new building should do the same.
- `main.fp_blocked()` lists what stops it or ends it: a story scene, sleep, the title, the knitting game, the cinematic camera, the world editor, building mode, playing the dog.

## Cinematic mode and the photo album: `scripts/cinematic.gd`, `scripts/photo_album.gd`

- P (or Menu > Cinematic camera) hands the camera to `main.cinema`. While `cinema.active`, `_update_camera()` returns at once, and `_input()` and `_unhandled_input()` give every key and mouse event to `cinema.handle_key()` and `cinema.handle_mouse()`. - Photos are PNGs in `Cinematic.dir` (`user://photos`). They are named `YYYY-MM-DD_HH-MM-SS_dayN_H-MMam.png`, so sorting by name puts the newest first. The album (`hud.album`, in the Esc menu) reads that folder each time it opens.

## Key bindings: `scripts/keybinds.gd`

- Settings > Key bindings… (`hud.open_keys()`) lists every action the player can move to another key, grouped by where it works (Moving, From above, First person, Cinematic camera, Knitting). A click on a key waits for the next one (`main._input` hands it to `hud.capture_key()`); Esc keeps the old key; Reset puts them all back. They're kept in `user://settings.cfg`, section `keys`, never written by the autotest (`Keys.persist`).
- The game's code still names each action by its default key. Pass a pressed key through `Keys.map(kc, groups)` before matching it (a bound key becomes its action's default key; a default key whose action moved becomes `KEY_NONE`), and read a held key through `Keys.key_for(default, groups)`. Groups: `move`, `world`, `fps`, `cine`, `knit`; walking (`move`) is live with the other three, so binding a key already used there swaps the two.
- A new key in the game: add it to `Keys.ACTIONS` (id, label, groups, default) and read it through `map` or `key_for`. Esc, Enter, the arrow keys and 1 to 9 are fixed (`Keys.FIXED`). The world editor, the pen builder and the wardrobe view keep their own keys.

## GDScript gotchas

- `:=` can't infer a type from a Variant. `Game.flag(...)`, `Game.stat(...)` and anything read from a Dictionary return Variant, so give the variable an explicit type: `var done: bool = Game.flag("act1_done") == true`. If you don't, the whole of `main.gd` fails to parse and the game won't start.
- Indent with tabs, and use static types wherever you can.
- Commit each `.uid` and `.import` file together with its script, shader or asset. Godot needs them. Never commit `.godot/` (it's in `.gitignore`).

Animation loops: the procedural bodies get theirs (Idle, Walk, SitKnit, SitIdle, Work, Talk) from Python pose functions in `build_character.py`. The Tripo models the game uses get motion-captured loops instead: `tools/retarget_anims.py` copies Idle, Walk, Brisk, Run (the Shift jog), Talk, SitIdle and Work from Quaternius's Universal Animation Library (CC0, free on itch.io, not in the repo) onto their rigs, and keeps their SitKnit. The order matters. Re-rigging a Tripo model with `rig_sculpt.py` brings back the procedural loops, so run the retarget after it:

```bash
Blender -b tools/character_build/nora_tripo/nora_tripo.blend -P tools/retarget_anims.py -- "$PWD" "<pack>/Unreal-Godot/UAL1_Standard.glb" nora_tripo
```

The collar bones are the one exception to copying the library's pose: each keeps its own rest and takes only the library collar bone's swing (a Mixamo collar bone rests 17 to 26 degrees below level, the library's lies level; aimed like the other bones it lifted the shoulders 8 to 19 cm in every loop). Lars, Max, Rosa and Sabrina still carry loops made before that fix (2026-11-15) and lose their slight shrug only when theirs are run again. `--arm-spread DEG` holds the arms further out, or closer in with a negative number: Barbara has -3, about 18 degrees out (at 26 she looked winged; at 14 her hands sink into her jacket's hips).

It prints each loop's stride speed (measured at the soles since 2026-11-13, so a rig made before then prints lower numbers than it has on file for the same loops: Barbara's legs didn't change). Put the Walk, Brisk and Run ones in `data/characters.json` (`walk_anim_speed`, `brisk_anim_speed`, `run_anim_speed`) so the feet don't slide. Brisk is the Walk clip with a longer stride (`Brisk=Walk_Loop*1.4`); `scripts/body.gd` changes to it above a stroll, so the player's 2 m/s walk isn't the stroll played at double speed. At `*1.7` it turns into a lunge.

Heads: `build_character.py`, `rig_sculpt.py` and `import_mixamo.py` all run `tools/rigid_head.py`, which binds everything from the jaw line up to the Head bone alone and fades that over 6 cm of neck, so a turned head never shears the face. The chin is found from the mesh: the first slice that juts 3.5 cm past the throat just under it, or, where no slice does (a chin that slopes into a full neck, like Rosa's, or a collar standing out under it), the first that juts 3.5 cm past the throat's deepest point. Its log line (`RIGID HEAD ... chin at`) should give a height a few centimetres below the mouth; at the Head bone's own height it found no chin, and the chin will twist with the neck (Rosa, Sabrina and Max did until 2026-11-14). The look-at in `scripts/rig.gd` spreads the turn over the spine, chest, upper chest, neck and head (`LOOK_BONES`; the spine and chest only turn, they don't nod), and turns then nods (no roll). Leave the spine out and a look to the side wrings the short neck like a rope. To fix a model rigged before this without re-rigging it: `Blender -b tools/character_build/<id>/<id>.blend -P tools/rigid_head.py -- "$PWD" <id>`, then run `add_eyes.py` for it again (it starts from that blend).

Seated story scenes: the seated loops put the seat at the character's origin, so `@place` takes a height after the yaw for anyone sitting on something above the ground (the date rock is 0.43).

Her grip: Nora's rig has no finger bones, so `tools/add_grip.py` adds a `grip_R` shape key to her body that curls her right hand's fingers into a fist round a handle across the palm, and the game turns it on while she holds a tool (`_update_held_tool` in `scripts/main.gd`, which puts each tool's handle through that fist: `FIST_C`, `TOOL_HOLD`). `add_eyes.py` starts its blend afresh, so run the grip after it: `Blender -b tools/character_build/nora_tripo_eyes/nora_tripo_eyes.blend -P tools/add_grip.py -- "$PWD" nora_tripo`, then import. `--review` adds the key without saving, for render checks. `--only=hud` saves a close-up of her fist round each tool, `47_fist_<tool>.png`. The same script makes her knitting hands: `knit_R` and `knit_L` close three fingers of each hand round a needle (the index finger nearly straight, the thumb on top), and `scripts/body.gd` turns them on with the SitKnit loop. It also turns SitKnit's arms palm down (`KNIT_TWIST`), keeps a fifth of its stroke (`KNIT_SWING`; at full swing the tips parted), swings the elbows out over the chair's arms with the hands left where they were (`KNIT_SPREAD`), all recorded on the action so a second run doesn't add to them, and lays the needles (the `KnitProps` mesh) through the two fists with the tips crossing, the work hanging from the left needle. The full autotest checks the knitting grip and saves `02d_knit_hands.png`.

Eyes: `tools/add_eyes.py` (rebuilt 2026-11-13 after Alex found the first eyes "terrible") cuts a clean almond opening in the head for each eye and puts a plain sphere eyeball behind it, with two thin lids on spheres round the same centre that close over it. Each eye's outline is measured by hand from the front map into the script's `EYES` table (`--probe` writes `_front_map.png`, `--region x0 x1 z0 z1` looks elsewhere, `--overlay` draws the outline over it to check). The painted eyes, their liner and lid lines are painted out of the albedo; a new lid rim rolls from the face into the opening, and the rim and lids use a seamless skin patch (`<id>_eyes_skin.png`) so there are no seams at the corners. The build log checks the head for torn or doubled edges and reports one clean loop round each opening. The cut runs along the head's own triangles, so its edge comes out saw-toothed: the script slides it smooth (never far enough to turn one of the head's faces over) and stitches the rim to it in order round the eye, so the strip between can't fold (folded, it showed as dark notches under Rowan's lids). Each eye's log line says how many stitch triangles still lie face down; a handful is fine. Paint touching the eye is painted out if it ends within `reach` of the outline (16 mm by default), and a mark's soft fringe goes with it. Re-rigging or re-targeting a model means running it again afterwards, since it starts from `tools/character_build/<id>/<id>.blend`. The six NPCs, Rosa, Max and Lars have the new eyes and play with them (Alex approved them on 2026-11-13: each one's `model` in `data/characters.json` is its `_eyes` GLB, and `model_painted_eyes` keeps the one before; Max's and Lars's irises are set larger, `iris=11.0`, or they stared; Lars's `loose=1` also paints out the lash flicks painted above his outer corners); Rebecca has had them since 2026-11-15 (her model has under 5,000 points, so the script takes the biggest mesh as the body; her round face falls away from the eyeball past the outer corners, where the lids can't stay under the skin, so past the corners the lids are skin right to their edge: the lash line had shown there as a dark dash beside each eye); Nora and Rowan have had them since 2026-11-14 (Nora with `reach=18`: her painted liner flicks out 17 mm). Run `add_grip.py` on Nora again after any rebuild of her eyes (see "Her grip" above). In the game, story lines set the speaker's mood on their eyes, `@eyes <who> closed|open|<mood>` does it without a line, and `body.set_eyes_closed()` shuts them for sleep.

## Rules

- **Never commit secrets.** That means API keys, tokens, `.env` files, passwords, certificates, and `.p8`/`.p12` keys.
- **Every character model gets real eyes.** Run `tools/add_eyes.py` on each new character and point its `model` in `data/characters.json` at the `_eyes` GLB, so it blinks, takes moods in story scenes and shuts its eyes asleep. Look at the review sheet before using it.
- **Every character model gets a rigid head.** Any new character, and any new tool that rigs or re-skins one, must run `tools/rigid_head.py` (`rigid_head.make_rigid(mesh, rig)`) before export, so the face turns in one piece. It stops with an error if anything above the jaw line still follows another bone. Check a new character with its head turned about 70°, close up.
- GitHub rejects files over 100 MB. Keep large source exports (Tripo GLBs, renders) out of the repo.
- Keep commits small, and write messages that say what changed and why.
- Text players will see (dialogue, story scenes, store or marketing copy) is a draft until Alex approves it.
