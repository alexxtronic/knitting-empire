# AGENTS.md

Notes for AI coding agents (Codex, Claude Code and others) working on Knitting Empire. People should start with `README.md`, which explains the game, the project layout and how to add content.

## The project

- A cozy farm, knitting and life-sim game made in **Godot 4.7** (GDScript, Forward+). Main scene: `main.tscn`. Most of the game logic is in `scripts/main.gd`, and the UI is in `scripts/hud.gd`.
- Content is data, not code. Furniture, crops, prices, villagers, dialogue and areas are in `data/*.json`, and story scenes are plain-text files in `data/scenes/*.scene`. To add content, edit the data first. `README.md` ("Adding content without code" and "Writing story scenes") explains the formats.
- The owner is Alex D'Amore. The art style rules are in `docs/STYLE_GUIDE.md` (a draft; don't treat it as final).

## Run it

```bash
/Applications/Godot.app/Contents/MacOS/Godot --path .
```

If you add or replace files under `assets/`, import them first. This writes their `.import` files:

```bash
/Applications/Godot.app/Contents/MacOS/Godot --headless --path . --import
```

## Test it: the autotest must pass

Every change to the game's code or data must keep the autotest green. A change that only adds or rebuilds an asset (a model, its textures, its `model` line in `data/furniture.json`) doesn't need the full run (Alex, 2026-11-12: "we don't need autotests for every single asset we make"): import it, run the matching quick check if there is one (`--only=house`, `--only=bench` and so on, a few seconds each) and look at its screenshot. The autotest opens a real game window (the renderer is needed, so it can't run headless) and plays through the game: farming, building, the town, the story (Act 1) and Rowan's romance scenes, plus sound, the title screen, settings and tips. It prints a `PASS` or `FAIL` line for each check and saves screenshots to the folder you give it. A full run takes about 6 to 8 minutes.

```bash
/Applications/Godot.app/Contents/MacOS/Godot --path . --resolution 1280x800 -- --autotest=/tmp/ke_shots > /tmp/ke_autotest.log 2>&1
grep -c '^PASS' /tmp/ke_autotest.log   # expect 236 at the time of writing
grep -E '^FAIL|SCRIPT ERROR|Parse Error' /tmp/ke_autotest.log   # expect nothing
```

## The world layout: `data/world_layout.json`

Alex arranges the map himself in the game: Settings > God mode > "Edit the world" (`scripts/god_mode.gd`; the switch only shows when the game runs from the project with the Godot editor build, never in an exported game). He can move, turn, copy and delete scenery and buildings, and paint dirt, gravel and cobblestone roads. It saves to `data/world_layout.json`, which every launch applies on top of what the code builds, so that file is the final map.

- Don't hand-edit or delete `data/world_layout.json`, and commit it when it changes. It is Alex's work.
- The autotest runs with the layout applied, because that's the game players get. If a check fails only because of where something now stands (a bench the test sits on was moved, say), fix the check to find the thing rather than the layout. `-- --nolayout` runs the game as the code builds it, to tell the two apart.
- Once a kind of scenery (a tree kind, rocks, a bush kind, tufts) has been edited, its full list is in the file and replaces what `world.gd` and `nature.gd` scatter. Changing their random placement no longer moves that kind. Single things (shop fronts, fountain, stall, signposts, barn, bin, plots, lamp posts, benches) are stored as changes named by kind and original position (`decor_lantern@46.00,-5.40`). If you move one in code, its saved change no longer matches: the game prints a `world layout:` warning and keeps the entry in the file.
- Nora's furniture (her house and the yard pieces a new game starts with, `main.furniture`) is editable too. Once any of it is arranged in the editor, the file gets a `"house"` list: the whole set as it stood, which `_new_world()` then furnishes a new game from instead of its built-in list. A catalog piece placed inside the house joins it. A player's own game keeps its furniture in the save.
- Guardrail: the god checks fail if any Furniture node in the world can't be picked up (on its own, or as part of something that can, like a shop's furnishings), or if any model in `assets/props` is missing from the Place list. If you add a new kind of thing that trips this, register it in `GodMode.collect()`; don't weaken the check.
- She can walk round every building wherever the editor puts it (`main.walk_areas()` adds the ground round each one to the walking grid). The grid covers x -96..144, z -100..62 (`GRID_ORIGIN`, `GRID_SIZE`; the lands round the farm make it that big).
- Anything new you add to the world should be editable too: build it as its own node and register it in `GodMode.collect()`, or scatter it as a MultiMesh under `nature` (those are picked up automatically). Loose boxes added straight to the world root can't be selected (the sheep pen and the pond were built that way at first). Every model in `assets/props` shows up in the editor's Place list by itself.
- The sheep pen can be moved: use `main.pen_rect`, not the `PEN` constant, for where it is now.
- Painted roads replace `World.PATHS`, `Town.PATHS` and the plaza cobbles as soon as the file has a `roads` entry. Read `god.road_at(x, z)` rather than those constants if you need to know what's underfoot.

- Rosewood Cottage is hidden for now (Alex, 2026-11-13): `Town.COTTAGE_ON` is false, so there's no cottage, for-sale sign or garden hedge, no sale on Gary's menu and no rent, and the town checks skip it (they check it's gone instead). An old save that bought it keeps the flag but gets nothing from it (`main.cottage_owned()`). Set it true to bring it all back.

## The lands round the farm: `scripts/regions.gd`, `data/regions.json`

- Four lands sit round the farm and Maple Grove, all in one continuous world (no loading screens): Mirewood Swamp to the west, Greyspine Foothills to the north with the mountain range behind them, Saltmeadow Beach and the sea to the south, Eastfield Meadows to the east. The names are draft text until Alex approves them.
- Each land's walkable rect, ground colours and scatter list are in `data/regions.json`; the `trails` there are the dirt paths that lead out to them. `Regions.build()` makes the ground, trails, swamp pools and mist, sea and mountains, and scatters the scenery as MultiMeshes under `main.nature`, one kind per land and model (`swamp-rock_cluster`), so the world editor can move them and the saved layout's lists for the farm's own kinds don't replace them.
- The mountains are one heightfield mesh behind the foothills (out of reach; she can't climb them). The sea is a plane with `shaders/sea.gdshader`; its shore is `regions.shore_z`. Far scenery fades out by `Regions.VIEW` distances to keep the frame rate up.
- If the world grows much further, stream far lands in and out by distance in the background rather than adding loading screens.

## The sun and the moon: `scripts/sky_bodies.gd`

- One DirectionalLight3D (`main.sun`) is the sun by day and the moon by night. `SkyBodies.update()` (called from `Lighting.update()`, after `main._update_lighting()`) points it at the sun, then swings it over to the moon during the dim part of dusk, or to faint high starlight when the moon is down. The sky shader draws both discs from `sun_dir` and `moon_dir`, not from the light.
- The moon goes round once a season by the game's days (`SkyBodies.phase()`, `LUNAR_DAYS` = 28): new on day 1, first quarter on the 8th, full on the 15th, last quarter on the 22nd, moving on a little each game hour. It trails the sun by its phase, so a full moon rises at sunset and is up all night. Moonlight runs from `MOON_NEW` to `MOON_FULL` with how much of the disc is lit, and the night's sky light goes with it. `SkyBodies.phase_override` fixes the phase for tests and screenshots.
- Clouds come and go on their own: `SkyBodies.cloudiness(day, hour)` drifts between clear, fair, broken and nearly overcast in spells of a few game hours, the same sky for the same day and hour every time. Rain covers the rest of the sky. A cloudier sky dims the sun a little and softens its shadows. `clouds_override` fixes it for tests.
- The grass has light and dark patches (`shaders/grass_patches.gdshaderinc`, shared by `ground.gdshader` and `grass_blade.gdshader` so the blades and the ground under them agree): broad sunnier and deeper drifts and smaller clumps. `patch_strength` on either material turns them down.
- `Lighting._depth()` works against the flat look by day: a stronger, warmer sun over a cool blue fill, a clearer sky at midday, and the distance fog kept off most of the sky (Godot fogs the sky fully by default, which had hidden the sky shader's gradient, clouds and stars).

- Post is a core mechanic (Alex, 2026-11-12). Barbara's nine o'clock round (`_update_post()` in `main.gd`) ends at Nora's mailbox (`mail.box`, by the porch; the world editor can move it) and calls `mail.post_call()`: she leaves what's due and takes any sweater Nora put out. ## The knitted sweaters: `scripts/sweaters.gd`, `data/sweaters.json`

- Fifty designs (Alex, 2026-11-13): 20 common, 15 rare, 10 ultra rare and 5 legendary, 1 to 4 stars. Names and stars are drafts. They're all one core sweater with a different colour map: `art/world_assets/sweater/patterns.py` draws each design stitch by stitch, and `build.py` there fits the sweater to a character and writes `data/sweaters.json`. Add or change a design in `patterns.py`, never in the JSON.
- `Sweaters.wear(body, design_id)` puts a design on any character who has a fitted sweater (`assets/sweaters/<id>_sweater.glb`; Nora and the villagers in `CHARS` in `build.py`), `take_off(body)` and `worn(body)`. The wool is `shaders/sweater.gdshader`: the design on UV, the stitch tiles (stockinette, or rib where the mask says) on UV2.
- The sweater goes on the character's own skeleton. Their body gets an `under_sweater` shape key that tucks the skin under the knit: the game's models don't carry it, so `sweaters.gd` adds it to a copy of the body mesh from `assets/sweaters/<id>_tuck.json` (points matched by position). Turn a character's sweater on only through `wear()`.
- Every sweater she carries has a design (`Game.sweater_designs`, in step with `Game.sweaters`): add one with `Game.add_sweater(rarity, design)` and take one out with `Game.remove_sweater(i)`, never by editing the arrays.
- Her wardrobe (Alex, 2026-11-13): `Game.wardrobe` (design -> rarity) holds one like every sweater she has knit, kept to wear; the ones in her bag are for selling. `Game.wear(design)` (or "" for her city coat) sets `worn_design` and `worn_quality` (her warmth). The wardrobe panel (`scripts/wardrobe_panel.gd`, `main.wardrobe_ui`) opens from a wardrobe piece in her house ("Choose a sweater…") or Menu > Wardrobe. A new house doesn't start with a wardrobe piece; it's in the catalogue. Knitting one warmer than what she wears puts it on.
- Villagers wear a sweater only once they buy one from her (Alex, 2026-11-13): their menu's "Sell a sweater to wear" rows (`_wear_sale_actions()`), one a day each, at Rosa's price for its rarity. What each wears is `Game.flags["npc_sweaters"]` (villager -> design), and `_update_sweater()` dresses them every frame from it. A gift doesn't dress them. The game's rarity still has five tiers (Common .. Legendary); `Sweaters.stars_for()` maps them onto the designs' four (Common and Uncommon are both one star).
- To fit another character: add them to `CHARS` in `build.py`, run it for them (Nora first; she sets the shared layout), import, and look at them in `--only=sweater`.

## First person: `scripts/first_person.gd`

- V (or Menu > First person) hands the camera to `main.fps`. Like cinematic mode, `_update_camera()` returns at once while `fps.active`; `_input()` asks `fps.handle_key()` first (keys it doesn't use, like the hotbar and the bag, go on as usual) and `_unhandled_input()` gives the mouse to `fps.handle_mouse()`. The clock runs and the HUD stays.
- The camera sits between her `LeftEye` and `RightEye` bones, `FirstPerson.FORWARD` in front, with most of the walk's head bob smoothed out (`BOB`). Her body turns with the view, and her head turns the way it looks (`_gaze_for`).
- WASD sets `player.steer`; `player.gd` walks her that way with her usual speeds and easing, sliding along anything `player.steer_ok` (the walking grid) says is solid. S plays the steps backward. A click's walk (an action on something far off) still uses her path.
- Her head is hidden from this camera only: her body meshes switch to shadows only (so her shadow keeps its head), and a copy of each without the triangles that follow the `Head` bone and the bones under it is drawn instead, sharing her skeleton and skin; their blend shapes (her grip, her knitting hands) are copied across each frame. The model isn't changed. If a character's hair or hat isn't weighted to the head, it would show.
- While it's on, the walls are up and every roof stays on round her.
- Roofs: every building has one, and they all follow one rule. From above (third person) a roof lifts off while she's inside, so you can see her; in first person it stays on. The barn (`World.update_barn`) and the walk-in shops (`Interiors.update`) lift theirs; Nora's house and Rosewood Cottage get a gable roof from `_house_roof()` in `main.gd` (shingled slopes, eaves, a plastered gable whose underside is the ceiling), and `_roof_lifted()` also lifts them in building mode, while placing a piece and in the world editor, so the rooms can be furnished. While a house's roof is on, all its walls stand: only a house with its roof lifted cuts the walls toward the camera down (`_update_walls`). The house's roof is rebuilt with it when it grows. A new building should do the same.
- `main.fp_blocked()` lists what stops it or ends it: a story scene, sleep, the title, the knitting game, a chat, the cinematic camera, the world editor, building mode, playing the dog.

## Cinematic mode and the photo album: `scripts/cinematic.gd`, `scripts/photo_album.gd`

- P (or Menu > Cinematic camera) hands the camera to `main.cinema`. While `cinema.active`, `_update_camera()` returns at once, and `_input()` and `_unhandled_input()` give every key and mouse event to `cinema.handle_key()` and `cinema.handle_mouse()`. Nothing reaches Nora, the clock is stopped and the HUD is hidden. On the way out it restores the camera's near and far planes, depth of field and shadow distance.
- Limits: `Cinematic.MAX_HEIGHT` (300 m), `GROUND_CLEAR` and `BOUNDS` (the map with plenty of room round it). It won't start in a story scene, asleep, knitting, on the title screen, in a chat or in the world editor.
- Photos are PNGs in `Cinematic.dir` (`user://photos`). They are named `YYYY-MM-DD_HH-MM-SS_dayN_H-MMam.png`, so sorting by name puts the newest first. The album (`hud.album`, in the Esc menu) reads that folder each time it opens.

## GDScript gotchas

- `:=` can't infer a type from a Variant. `Game.flag(...)`, `Game.stat(...)` and anything read from a Dictionary return Variant, so give the variable an explicit type: `var done: bool = Game.flag("act1_done") == true`. If you don't, the whole of `main.gd` fails to parse and the game won't start.
- Indent with tabs, and use static types wherever you can.
- Commit each `.uid` and `.import` file together with its script, shader or asset. Godot needs them. Never commit `.godot/` (it's in `.gitignore`).

Each eye's outline is measured by hand from the front map into the script's `EYES` table (`--probe` writes `_front_map.png`, `--region x0 x1 z0 z1` looks elsewhere, `--overlay` draws the outline over it to check). The painted eyes, their liner and lid lines are painted out of the albedo; a new lid rim rolls from the face into the opening, and the rim and lids use a seamless skin patch (`<id>_eyes_skin.png`) so there are no seams at the corners. The build log checks the head for torn or doubled edges and reports one clean loop round each opening. The cut runs along the head's own triangles, so its edge comes out saw-toothed: the script slides it smooth (never far enough to turn one of the head's faces over) and stitches the rim to it in order round the eye, so the strip between can't fold (folded, it showed as dark notches under Rowan's lids). Each eye's log line says how many stitch triangles still lie face down; a handful is fine. Paint touching the eye is painted out if it ends within `reach` of the outline (16 mm by default), and a mark's soft fringe goes with it. Re-rigging or re-targeting a model means running it again afterwards, since it starts from `tools/character_build/<id>/<id>.blend`. ## Rules

- **Never commit secrets.** That means API keys, tokens, `.env` files, passwords, certificates, and `.p8`/`.p12` keys. Villager chat needs an Anthropic API key, but it is never stored in the repo or the game. Players paste it into the game (it's saved in Godot's user folder) or set `ANTHROPIC_API_KEY`. Don't add a key, a default key or a key file to the project.
- **Every character model gets real eyes.** Run `tools/add_eyes.py` on each new character and point its `model` in `data/characters.json` at the `_eyes` GLB, so it blinks, takes moods in story scenes and shuts its eyes asleep. Look at the review sheet before using it.
- **Every character model gets a rigid head.** Any new character, and any new tool that rigs or re-skins one, must run `tools/rigid_head.py` (`rigid_head.make_rigid(mesh, rig)`) before export, so the face turns in one piece. It stops with an error if anything above the jaw line still follows another bone. Check a new character with its head turned about 70°, close up.
- GitHub rejects files over 100 MB. Keep large source exports (Tripo GLBs, renders) out of the repo.
- Keep commits small, and write messages that say what changed and why.
- Text players will see (dialogue, story scenes, store or marketing copy) is a draft until Alex approves it.
